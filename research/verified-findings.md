## 6. Privacy, user control and safety

- **Own current policy:** [yoxi privacy](https://www.yoxi.app/privacy) describes information categories and data uses; this is **not** blanket authorization for new continuous background calendar/location collection or cross-product sharing. Need separate purpose/consent analysis.
- **Apple notifications:** Obtain opt-in; give in-app granular preferences, quiet hours, caps, dedup, dismiss/snooze. Apple says marketing alerts should not use Time Sensitive priority ([Apple guidance](https://developer.apple.com/design/human-interface-guidelines/managing-notifications)).
- **Calendar access:** On supported iOS, reading user events requires authorization, not automatically conferred by basic app membership ([EventKit](https://developer.apple.com/documentation/EventKit/accessing-calendar-using-eventkit-and-eventkitui)). Default to selective/manual/deny-respectful flows.
- **Minimize data:** proposed privacy design = local/on-device rule gating where possible, event-derived feature summaries rather than full event details, bounded retention, delete/export/disable controls, clear notification rationale and freshness timestamp. **PROPOSED architecture controls; no implementation audited**.
- **Travel controls:** A user must affirmatively confirm destination/pickup, displayed fare/terms and booking. Weather/transit failure suppresses risky claims and falls back to ordinary one-tap ride booking or plain non-live guidance.
